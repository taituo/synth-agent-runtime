# Kubernetes execution design

## Goal

Keep logical agents cheap and durable while using Kubernetes only for effects
that require a real process/kernel/service environment.

```text
500 logical agents
      |
      +-- most work -> RAM/synthetic
      |
      `-- selected process.exec effects
                |
                v
          bounded warm pool
          2..N gVisor Pods
```

A Pod is a lease, not an agent.

## Resource classes

The built-in profiles live in `src/execution/resource-class.ts`:

- `sandbox-small`
- `sandbox-medium`
- `sandbox-heavy`
- `project-cell`

Each profile controls runtime class, requests/limits, ephemeral storage,
workspace medium, timeout, networking and warm-pool policy.

## Isolation

Executor Pod manifests are generated by `buildSandboxPod()` and network policy
by `buildSandboxNetworkPolicy()`.

Default executor boundary:

```text
runtimeClassName: gvisor
automountServiceAccountToken: false
runAsNonRoot: true
allowPrivilegeEscalation: false
privileged: false
capabilities.drop: [ALL]
seccompProfile: RuntimeDefault
readOnlyRootFilesystem: true
no hostPath / no Docker socket
```

The root filesystem is read-only; only `/workspace` and `/tmp` are writable
`emptyDir` volumes.

## Network

Normal sandboxes use an egress-proxy policy:

```text
sandbox
  -> kube-dns:53
  -> synth-egress-proxy:3128
  X  direct Internet
  X  arbitrary cluster services
```

ProjectCells instead get cell-local service connectivity plus DNS.

## Warm pool

`WarmSandboxPool` bounds both warm and total Pods. On release:

1. reset `/workspace` and `/tmp`
2. if reset succeeds, return to ready pool
3. if reset fails, destroy Pod
4. idle excess Pods are reaped

## Workspace materialization

Default v0.2 mode keeps private repository credentials outside the Pod:

```text
trusted NativeGitSource (shallow/partial/sparse)
                 |
                 | file bytes
                 v
        WorkspaceSynchronizer
                 |
                 v
            /workspace
```

A local Git baseline is created in the Pod. The RAM overlay is applied after
that baseline. After the command, `git status --porcelain` identifies changed
source files; only bounded file contents are read back into `MemoryWorkspace`.

## ProjectCell

A ProjectCell is a longer-lived isolated namespace:

```text
synth-cell-project-x
├ executor
├ postgres (optional)
├ redis (optional)
└ browser (optional)
```

The agent receives addresses, not Kubernetes credentials. The runtime owns
leases and idle reaping.

## Physical effect

```ts
await context.executeEffect?.({
  id: "test",
  kind: "process.exec",
  command: "npm test",
  resourceClass: "sandbox-small",
  timeoutMs: 120_000,
});
```

The same logical workspace continues after the Pod disappears.
